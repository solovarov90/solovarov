Claude Code на сервере по подписке превращается в ИИ-агента в Telegram за один вечер: небольшой Telegram-бот принимает сообщение, передаёт его в `claude -p` и возвращает ответ в чат. Claude Code входит в аккаунт по обычной подписке Claude Pro или Max, поэтому API-ключ не нужен и оплаты за каждый запрос нет. Я работаю так с 30 сентября 2026 года: из телефона ставлю задачи по коду, правлю базы в Notion, запускаю монтаж роликов и пишу статьи.

Как устроен мой штаб целиком, я разбирал в [статье про управление Claude Code с телефона](/blog/upravlyat-claude-code-s-telefona/), а файл службы и вход без экрана по шагам есть в [инструкции про Claude Code как сотрудника](/blog/claude-code-kak-sotrudnik-v-telegram/). Здесь другая задача: собрать минимальную рабочую версию за вечер, дать ей навыки и память и не упереться в лимиты. Плюс две свежие ловушки из документации Anthropic, о которых я раньше не писал.

## Зачем запускать Claude Code как агента в Telegram, а не держать в консоли?

Агент в Telegram работает, когда ноутбук закрыт, и доступен с телефона в любой момент. В консоли Claude Code живёт ровно столько, сколько открыто окно терминала. На сервере он ждёт задачу круглосуточно, а Telegram даёт ему готовый интерфейс: текст, голосовые, файлы, кнопки.

Агентом я называю программу, которая сама решает, какие шаги сделать: прочитать файл, поправить код, сходить в Notion. Чат-бот отвечает текстом. Агент делает работу и отчитывается.

Что это даёт на практике:

- **Задача из любого места.** Я наговариваю голосовое «в сценарии REEL-6 убери второй хук», бот переводит его в текст, Claude правит страницу в Notion и пишет, что сделал.
- **Длинные задачи без присмотра.** Монтаж или статья идут десятки минут. Я отправил задачу и занимаюсь своим, статус приходит в ту же тему.
- **Одна точка входа.** Все участки работы разложены по темам одной Telegram-группы, и по теме бот понимает, какие правила подложить Claude.

Если тебе нужен помощник для бизнеса своими руками, это самый короткий путь: сервер, подписка и бот на сотню строк. Код агента писать не нужно, агент уже есть.

## Что нужно для старта: выбор сервера, подписка и права доступа?

Нужны три вещи: недорогой Linux-сервер, подписка Claude Pro или Max и отдельный пользователь для бота. Мой штаб живёт на Hetzner с 2 ядрами и 3,7 ГБ памяти, по данным на 30.09.2026 свободно было около 2,9 ГБ, диск занят на 25%. Сервер для ботов у меня стоит от 500 рублей в месяц, эту цифру я разбирал в [статье про медиа-конвейер](/blog/media-konveyer-na-ii/).

Про подписку. В моём [руководстве по настройке Claude](https://app.notion.com/p/Claude-60-3efdfdb1482281f29f6ede5d1c6f2e0a) на 04.10.2026 записано: Pro стоит $20 в месяц или $17 при оплате за год, Claude Code входит в платные тарифы. [Справка Anthropic](https://support.claude.com/en/articles/11145838-using-claude-code-with-your-pro-or-max-plan) (проверено 19.10.2026) подтверждает, что подписка Pro и Max покрывает Claude Code в терминале.

Список на вечер:

1. **Сервер на Ubuntu.** Наружу открыт только SSH.
2. **Node.js и npm.** Claude Code ставится через npm.
3. **Python.** На нём пишется бот, подойдёт любая библиотека для Telegram-ботов.
4. **Отдельный пользователь.** У меня это `iishtab`. От него работают и бот, и Claude Code, вход в подписку хранится в его домашней папке.
5. **Токен бота** от @BotFather и id твоего аккаунта в Telegram, чтобы бот слушал только тебя.

Про права сразу одно правило. Claude Code ставь от root, а работай от пользователя бота. Тогда агент не может сломать систему, а ты точно знаешь, кто что обновляет. Обратная сторона этого правила стоила мне вечера, о ней в разделе «Проверил на себе».

Видеокарта и графический интерфейс на сервере не нужны. Вход в подписку делается по ссылке: Claude Code печатает её в терминале, ты открываешь её на телефоне и вставляешь код обратно.

## Как связать Telegram-бота с неинтерактивным режимом claude -p?

Бот запускает `claude -p "текст задачи"` как обычную программу, ждёт, пока она закончит, и отправляет ответ в чат. `claude -p` это неинтерактивный режим: задача передаётся одной строкой, Claude выполняет её и печатает результат. Всё остальное это обвязка вокруг одного вызова.

В [документации Anthropic](https://code.claude.com/docs/en/headless) (проверено 21.10.2026) у этого режима есть всё, что нужно боту:

- `--output-format json` отдаёт ответ с полями `result` и `session_id`, бот легко их разбирает;
- `--resume <id сессии>` продолжает прошлый разговор, так Claude помнит, о чём шла речь в теме;
- `--allowedTools` перечисляет инструменты, которыми агенту можно пользоваться без вопроса.

Ядро бота выглядит примерно так. Это схема, имена и пути подставь свои:

```python
import asyncio, json

lock = asyncio.Lock()          # очередь на одного Claude
sessions = {}                  # тема -> id сессии

async def run_claude(topic, text):
    cmd = ["claude", "-p", text, "--output-format", "json",
           "--allowedTools", "Read,Edit"]
    if topic in sessions:
        cmd += ["--resume", sessions[topic]]
    async with lock:
        proc = await asyncio.create_subprocess_exec(
            *cmd, cwd="/opt/my-agent/workspace",
            stdout=asyncio.subprocess.PIPE)
        try:
            out, _ = await asyncio.wait_for(proc.communicate(), timeout=1800)
        except asyncio.TimeoutError:
            proc.kill()
            return "Не уложился во время, задачу остановил."
    data = json.loads(out)
    sessions[topic] = data["session_id"]
    return data["result"]
```

Три строки здесь важнее остальных. Замок `lock` пускает одного Claude за раз: на сервере с 4 ГБ памяти две сессии сразу уже риск. Таймаут убивает зависший запуск, иначе одна задача держала бы очередь вечно. Словарь `sessions` даёт каждой теме свою память разговора.

Теперь две ловушки, которые я нашёл в документации, когда готовил эту статью.

**Флаг `--bare`.** Он ускоряет запуск и пропускает навыки, `CLAUDE.md`, MCP-серверы и память. Документация на 21.10.2026 прямо пишет: в этом режиме Claude Code не читает вход по подписке, ему нужен `ANTHROPIC_API_KEY`. И добавляет, что `--bare` в будущих версиях станет режимом по умолчанию для `-p`. Для агента на подписке это значит одно: после каждого обновления проверяй, что ответ пришёл по подписке.

**Режим Manual.** С версии 2.1.302 запуск `claude -p` без явного режима разрешений стартует в Manual. Действие, которому нужно подтверждение, будет отклонено: спросить некого. Поэтому всё, что агенту можно делать, перечисли заранее в `--allowedTools` или задай режим через `--permission-mode`.

И старая ловушка, о которой предупреждает [справка Anthropic](https://support.claude.com/en/articles/11145838-using-claude-code-with-your-pro-or-max-plan): если на машине задана переменная `ANTHROPIC_API_KEY`, Claude Code возьмёт ключ вместо подписки, и запросы пойдут в оплату по API. На сервере, где раньше жили другие проекты, ключ легко пропустить.

## Как настроить навыки, память агента и подключение к внешним базам?

Память агента это файлы в рабочей папке, которые Claude Code читает сам при каждом запуске. Главный из них `CLAUDE.md`: описание проекта, где что лежит, правила и запреты. Навыки лежат в `.claude/skills`, внешние базы подключаются коннекторами и MCP-серверами.

MCP это общий способ подключить к Claude внешний инструмент: базу, поиск, свой сервис. Коннектор это готовый мост от Claude к сервису вроде Notion, ключи для него на сервере хранить не нужно.

Как это разложено у меня:

1. **`CLAUDE.md`.** Проект, адреса баз в Notion, серверы, правила тона и одно жёсткое правило: каждое решение записывать строкой в журнал изменений. Поэтому короткое «перепиши REEL-6» Claude понимает без пояснений.
2. **Навыки.** Навык (скилл) это инструкция на одну задачу: разобрать ролик, написать статью по брифу. Claude подключает его, когда задача подходит. Эту статью написал навык блога.
3. **Notion через коннектор.** Агент штаба читает и правит «Контент-план», журнал, страницы стратегии.
4. **Свой MCP-сервер.** С 18.10.2026 у штаба есть «второй мозг»: индекс моих знаний из Notion, сайта и заметок, по [журналу изменений](https://app.notion.com/p/SEO-MCP-brain-3fddfdb148228124b001cee52f2ad194) на старте 4 344 куска. Агент ищет в нём факты инструментом `brain_search`, и свои цифры в статьях берёт только оттуда.

Память разговора и память проекта это разные вещи. Разговор держит `--resume`, и он со временем протухает: когда сессия перестаёт открываться, бот начинает разговор заново. Всё, что должно пережить новую сессию, кладу в `CLAUDE.md` или в Notion. Правило простое: если я объяснил агенту что-то второй раз, это пора записать в файл.

Совет из практики: пиши `CLAUDE.md` как памятку новому сотруднику. Что за проект, кто автор, где база, чего делать нельзя. И держи его коротким, потому что этот файл попадает в каждый запуск и расходует лимит.

Что идёт через штаб каждый день:

- **Сценарии роликов.** С 04.10.2026 хуки, текст и концовки пишет Claude Opus 5.5 по подписке, сценарий REEL-19 переписался примерно за 33 секунды.
- **Статьи блога.** С 18.10.2026 SEO-штаб пишет их через `claude -p` с навыком блога, это занимает 10–25 минут. Ему разрешена ровно одна команда в терминале: проверка текста на штампы.
- **Разговор с продюсером.** С 19.10.2026 его ведёт Claude Opus. По [журналу изменений](https://app.notion.com/p/Claude-Opus-3fedfdb148228153b0fef9c196ab295c) Notion он только читает, а процессы других ботов запускает командами из белого списка и только по моей кнопке «Запустить».
- **Файлы.** С 01.10.2026 бот ходит в Telegram через свой локальный сервер Bot API и принимает файлы до 2 ГБ вместо 20 МБ. Так в штаб приезжают сырые видеодубли.

Теперь ошибки.

**Новая модель и старая версия.** 04.10.2026 я переводил сценарии с Gemini Flash на Claude Opus 5.5. Бот стал вызывать `claude -p --model claude-opus-5-5`, а Claude Code ответил отказом: стояла версия 2.1.251, она такой модели не знала. Штатное `claude update` от пользователя бота падало: npm-пакеты стояли от root, прав у пользователя не было. Автообновление молча не работало с первого дня. Я обновил Claude Code от root до 2.1.289, проверил вызов Opus от пользователя бота, и с тех пор обновляю только так.

**Лимит посреди монтажа.** 01.10.2026 первый монтаж из чата упёрся в лимит подписки на шаге 4 из 7. В тот же день появилась кнопка «Продолжить»: Claude поднимает ту же сессию через `--resume` и не повторяет готовые шаги. Следом автоожидание: задача встаёт на паузу до сброса лимита, в статусе пишется время продолжения. По [журналу изменений](https://app.notion.com/p/Claude-3ecdfdb14822811da1a8ecc18d22b69a), три дубля в тот день продолжились сами после сброса в 16:39.

**Ввод в SSH.** Встроенная панель терминала в приложении не передавала ввод в SSH, и код входа в подписку не вставлялся. Помогло обычное отдельное окно командной строки. Мелочь, но на ней легко потерять час.

## Сколько ресурсов ест связка и как не упереться в лимиты подписки?

Сервер с 2 ядрами и 4 ГБ памяти держит одного агента спокойно, если Claude работает строго по одному. Узкое место здесь подписка: лимит считается окнами по 5 часов плюс общая недельная квота, так записано в моём руководстве по Claude на 04.10.2026. Там же отмечено, что чат и Claude Code тратят один общий пул.

У меня на одной подписке живут три бота, и в каждом стоит очередь на одного Claude. Ночные задачи вроде отбора тем из трендов не пересекаются с дневной работой, иначе они делят одно окно лимита.

Что съедает лимит быстрее всего и что я с этим делаю:

| Что расходует лимит | Что делаю |
|---|---|
| Длинные задачи: монтаж, статья | Запускаю по одной, после лимита продолжаю через `--resume` |
| Длинный разговор в одной сессии | Отдельная сессия на каждую тему, история не тянется в каждый запрос |
| Толстый `CLAUDE.md` | Держу коротким, подробности выношу в навыки |
| Параллельная работа в чате claude.ai | Помню, что пул общий, тяжёлое ставлю на ночь |
| Зависший запуск | Таймаут убивает процесс, бот пишет в тему |

Проверь ещё одно: стоимость в ответе. С `--output-format json` Claude Code кладёт в ответ поле `total_cost_usd`. Документация уточняет, что это оценка на стороне клиента, и счёт она не означает. Мне это поле удобно как грубый счётчик: видно, какие задачи тяжёлые, и их стоит дробить.

Длинные задачи ты почувствуешь в лимите точно. Поэтому тяжёлое у меня идёт по расписанию и с автопродолжением, а лёгкое отвечает сразу.

## Что может сломаться и как это предупредить?

Связка ломается на стыках: права пользователей, версии, лимиты, протухшие сессии и окружение. Вот что я проверяю на каждом новом сервере.

- **`ANTHROPIC_API_KEY`.** Его не должно быть ни в `env` пользователя бота, ни в `.bashrc`, ни в файле службы.
- **`--bare` в команде.** Вход по подписке в этом режиме не читается. Если однажды режим станет умолчанием, проверяй это после обновления.
- **Версия Claude Code.** Новая модель в подписке не значит, что старая версия её примет. После обновления от root проверяй `claude --version` и вызов нужной модели от пользователя бота.
- **Разрешения.** В режиме Manual всё, что требует подтверждения, отклоняется. Начни с узкого `--allowedTools` и расширяй по одной задаче.
- **Ключи к другим серверам.** У меня ключ штаба к соседнему серверу разрешает ровно одну команду: запустить разбор ссылки. Больше ничего с ним сделать нельзя.

Опасные действия, вроде деплоя и включения служб, я агенту не отдаю, делаю их сам. Агент готовит, человек нажимает.

## Пошаговый план: как развернуть своего ИИ-сотрудника за один вечер?

За вечер реально собрать бота на одну тему и одну задачу. Штаб из двадцати функций за вечер не собирается, а помощник, который делает одну твою рутину, собирается. Порядок такой:

1. **Сервер.** Ubuntu, 2 ядра и 4 ГБ памяти, наружу только SSH.
2. **Пользователь и Claude Code.** Создай пользователя для бота. От root поставь Claude Code: `npm install -g @anthropic-ai/claude-code`.
3. **Вход по подписке.** От пользователя бота запусти `claude`, открой ссылку на телефоне, войди аккаунтом с Pro или Max, вставь код.
4. **Проверка окружения.** `claude -p "привет"` от того же пользователя отвечает, `ANTHROPIC_API_KEY` в окружении нет.
5. **Рабочая папка.** `CLAUDE.md` на одну страницу: что за проект, где база, что нельзя.
6. **Бот на одну тему.** Ядро из примера выше: замок на одного, таймаут, сессия темы, узкий `--allowedTools`. Бот отвечает только твоему id.
7. **Служба systemd.** Чтобы бот переживал перезагрузку сервера. Пример файла службы есть в [инструкции про Claude Code как сотрудника](/blog/claude-code-kak-sotrudnik-v-telegram/).
8. **Первая задача.** Например, «добавь строку в базу Notion» через коннектор. Пусть поработает неделю.

Дальше добавляй по одной вещи: вторую тему, навык под повторяющуюся задачу, локальный Bot API для больших файлов, автопродолжение после лимита. И веди журнал изменений с первого дня: через месяц он скажет, что и когда сломалось.
