Запустить Claude Code как сотрудника в Telegram можно на недорогом Linux-сервере: бот принимает задачу из чата и передаёт её в `claude -p`, а сам Claude Code вошёл в аккаунт по обычной подписке Claude Pro. API-ключ не нужен, ты платишь за подписку и сервер. Я так работаю с 30 сентября 2026 года: со смартфона ставлю задачи по коду, правлю базы в Notion, запускаю монтаж роликов и пишу статьи.

Ниже инструкция по шагам: какой сервер взять, как войти в Claude на машине без экрана, как завернуть бота в службу, как передавать файлы, как дать агенту правила и где он ломается. Всё описанное работает внутри моего проекта ii.systema каждый день. Как я пользуюсь этим штабом с телефона, я уже разбирал в [отдельной статье](/blog/upravlyat-claude-code-s-telefona/). Здесь упор на сборку.

## Как работает связка Telegram-бота и Claude Code без платного API?

Связка из трёх частей: Telegram-группа, бот-курьер на сервере и Claude Code в рабочей папке с правилами. Бот сам ничего не думает. Он получает сообщение, понимает, из какой оно темы, запускает `claude -p` с текстом задачи и отправляет ответ обратно в ту же тему.

`claude -p` это неинтерактивный режим Claude Code. Задача передаётся одной строкой, Claude выполняет её и печатает результат. В [документации Anthropic](https://docs.claude.com/en/docs/claude-code/headless) (проверено 19.10.2026) у этого режима есть всё, что нужно боту:

- `--output-format json` отдаёт ответ в виде, который бот легко разбирает;
- `--resume <id сессии>` продолжает прошлый разговор, так Claude помнит, о чём шла речь в теме;
- `--allowedTools` задаёт инструменты, которыми агенту разрешено пользоваться.

Агентом я называю программу, которая сама решает, какие шаги сделать: прочитать файл, поправить код, сходить в Notion. Этим Claude Code и отличается от чат-бота. Ты пишешь «перепиши сценарий REEL-6 по свежим правилам», а он сам находит сценарий, читает правила, переписывает и сохраняет.

API здесь это платный программный доступ к модели, где каждый запрос оплачивается по объёму текста. Подписка устроена иначе: фиксированная цена в месяц и лимит по окнам. В моём гайде по Claude на 04.10.2026 записано, что Pro стоит $20 в месяц или $17 при оплате за год, а лимит считается окнами по 5 часов. Для агента, который за одну задачу читает десятки файлов, это сильно спокойнее, чем счёт за токены.

Я не первый, кто к этому пришёл. Например, проект [Orca](https://github.com/stablyai/orca) обещает следить за агентами вроде Claude Code с телефона и отправлять им задачи откуда угодно (так написано на странице проекта 19.10.2026). Свой бот мне удобнее: он знает мои темы, мои базы и мои правила.

## Какой сервер нужен для запуска автономного ИИ-агента?

Хватит небольшого облачного сервера на Ubuntu. Мой штаб живёт на Hetzner с 2 ядрами и 3,7 ГБ памяти. По данным на 30.09.2026 из памяти было свободно около 2,9 ГБ, диск занят на 25%, свободно около 27 ГБ. Сервер для ботов у меня стоит от 500 рублей в месяц, эту цифру я разбирал в [статье про медиа-конвейер](/blog/media-konveyer-na-ii/).

Главное ограничение здесь память. Одна сессия Claude Code на таком сервере работает спокойно. Две одновременно уже рискованно. Поэтому в боте с первого дня стоит очередь на одного: работает один Claude, остальные задачи ждут.

Что поставить на сервер:

1. **Node.js и npm.** Claude Code ставится через npm.
2. **Python.** На нём написан мой бот, подойдёт любая библиотека для Telegram-ботов.
3. **Отдельного пользователя.** У меня это `iishtab`. От него работают бот и Claude Code, у него своя домашняя папка и свои права.
4. **Рабочую папку проекта.** В ней лежат правила для агента и навыки, об этом ниже.

Чего не нужно: видеокарты, графического интерфейса, браузера на сервере. Тяжёлое, вроде монтажа роликов, у меня идёт на домашнем компьютере, а сервер передаёт туда задачи через синхронизацию папок.

## Как авторизовать Claude Code под подпиской Pro на сервере без экрана?

Вход делается прямо в терминале по SSH. Запускаешь Claude Code, он печатает ссылку, ты открываешь её в браузере на телефоне или ноутбуке, входишь аккаунтом с подпиской и вставляешь код обратно в терминал. Браузер на сервере не нужен.

Порядок, который работает у меня:

1. Зайди на сервер по SSH и переключись на пользователя бота: `sudo -iu iishtab`. Входить надо под ним, потому что вход сохраняется в его домашней папке.
2. Поставь Claude Code от root: `npm install -g @anthropic-ai/claude-code`.
3. От пользователя бота запусти `claude` или `claude auth login`. Появится ссылка.
4. Открой ссылку где угодно, войди аккаунтом с Pro и скопируй код в терминал.
5. Проверь: `claude -p "привет"` от того же пользователя. Ответ пришёл, значит бот тоже сможет.

Сразу после входа проверь окружение. [Справка Anthropic](https://support.claude.com/en/articles/11145838-using-claude-code-with-your-pro-or-max-plan) (проверено 19.10.2026) предупреждает: если на машине задана переменная `ANTHROPIC_API_KEY`, Claude Code возьмёт этот ключ вместо подписки, и запросы пойдут в оплату по API. На сервере, где раньше жили другие проекты, ключ легко пропустить. Посмотри `env` пользователя бота, его `.bashrc` и файл службы.

## Как завернуть бота в службу, чтобы он работал круглосуточно?

Бота стоит запустить как службу systemd. Systemd сам поднимает его после перезагрузки сервера и после падения. У меня бот @ii_systemaBot работает службой `ii-shtab` от пользователя `iishtab`.

Файл службы выглядит примерно так, пути подставь свои:

```
[Unit]
Description=Telegram-бот поверх Claude Code
After=network-online.target

[Service]
User=iishtab
WorkingDirectory=/opt/ii-shtab
ExecStart=/opt/ii-shtab/venv/bin/python bot.py
Restart=always

[Install]
WantedBy=multi-user.target
```

Дальше `systemctl enable --now ii-shtab`, и бот живёт сам. Логи смотрю через `journalctl -u ii-shtab`.

Внутри бота главное это функция запуска Claude. Она собирает команду `claude -p`, добавляет правила темы, список разрешённых инструментов и номер прошлой сессии. Если сессия протухла, бот повторяет запрос с новой сессией. Вокруг функции стоит замок на одного: пока работает один Claude, следующая задача ждёт.

Состояние бота храню в файле на диске: какие задачи в работе, какие сессии у тем, что ждёт ответа. Поэтому перезапуск службы ничего не теряет. Для бота, который ведёт задачи часами, это обязательно: иначе каждое обновление кода обрывает работу на середине.

## Как передавать задачи и файлы из Telegram прямо в проект?

Текстовая задача уходит в Claude как есть, вместе с правилами темы. Файл бот скачивает в рабочую папку и передаёт Claude путь к нему. Дальше агент работает с ним как с обычным файлом: читает, правит, кладёт результат рядом.

Подводный камень в размере. Обычный облачный Bot API отдаёт ботам файлы до 20 МБ. Для документов хватает, для видео нет. Поэтому с 01.10.2026 мой бот ходит в Telegram через свой сервер Bot API, развёрнутый на той же машине. Он принимает файлы до 2 ГБ, и в штаб приезжают даже сырые видеодубли.

Как я раскладываю задачи по темам группы:

- **«Штаб».** Разговор, правки в Notion, голосовые. Голосовое бот переводит в текст и отдаёт Claude.
- **«Референсы».** Ссылка на чужой ролик сразу уходит на разбор.
- **«Сценарии».** Готовые тексты к записи и кнопки «переписать».
- **«Дубли», «Монтаж», «Выкладка».** Видео, статусы монтажа и публикации.

Принцип один: одна тема, один участок работы. Бот по теме понимает, какие правила подложить Claude и какие инструменты ему открыть. В теме разговора агенту можно читать и править Notion, в теме выкладки у него свой узкий набор действий.

Голосовые сильно экономят время. Я наговариваю «в сценарии REEL-6 убери второй хук и сделай концовку короче», бот расшифровывает, Claude правит страницу в Notion и отвечает, что сделал.

## Как подключить к агенту базы знаний и правила через CLAUDE.md?

Правила агента живут в файле `CLAUDE.md` в рабочей папке. Каждая новая сессия Claude Code читает его первой. В нём описан проект, где что лежит и по каким правилам работать. Поэтому короткое сообщение «перепиши REEL-6» Claude понимает без пояснений.

Что у меня лежит в рабочей папке:

1. **`CLAUDE.md`.** Описание проекта, адреса баз в Notion, серверы, правила тона, правило записывать каждое решение строкой в журнал изменений.
2. **Навыки в `.claude/skills`.** Навык (скилл) это инструкция на одну задачу: разобрать ролик, написать статью по брифу. Claude подключает его, когда задача подходит.
3. **Коннекторы.** Через коннекторы claude.ai агенту доступен Notion. Коннектор это готовый мост от Claude к внешнему сервису, ключи для него на сервере хранить не нужно.

Совет из практики: пиши `CLAUDE.md` как памятку новому сотруднику. Что за проект, кто автор, где база, чего делать нельзя. Чем конкретнее правила, тем реже приходится объяснять одно и то же в каждой задаче.

Если агенту нужны файлы из другой папки, их открывают флагом `--add-dir`. Мой SEO-штаб так пишет статьи: Claude работает из папки штаба, где лежат правила и навыки, и получает доступ к клону сайта, куда сохраняет статью.

## Что делать с правами доступа и фоновым обновлением пакетов?

Права задаются заранее, потому что в режиме `claude -p` спросить подтверждение не у кого. Разрешённые инструменты перечисляются в `--allowedTools`, и всего, чего нет в списке, Claude не сделает. Опасные действия, вроде деплоя и включения служб, я оставляю себе руками.

Как это выглядит у меня на практике:

- **Узкие команды в shell.** Статьи SEO-штаб пишет с разрешением запускать ровно одну проверку текста: `Bash(python3 /opt/ii-seo/speech_check.py:*)`. Любую другую команду в терминале агент там запустить не может.
- **Ключи на одну команду.** Разбор видео идёт на соседнем сервере. Ключ штаба к нему разрешает ровно одну команду: запустить разбор. Ключ для закрытого превью статей разрешает только копирование файлов в одну папку.
- **Запуск по кнопке.** С 19.10.2026 разговор в боте-продюсере ведёт Claude Opus. Notion он только читает. Процессы других ботов, например монтаж или выкладку, он предлагает командами из белого списка, а запускаются они только по моей кнопке «Запустить».

Теперь про обновления. Claude Code ставится через npm от root, а бот работает от своего пользователя. Штатная команда `claude update` от пользователя бота поэтому падает: ей некуда писать. У меня автообновление молча не работало с первого дня, и я узнал об этом только тогда, когда понадобилась новая модель.

Правило, которое я записал после этого:

1. Обновлять от root: `npm install -g @anthropic-ai/claude-code@latest`.
2. После обновления проверить `claude --version` и вызов нужной модели от пользователя бота.
3. Записать обновление строкой в журнал изменений.

## С какими поломками и лимитами ты столкнёшься при долгой работе?

Связка ломается на стыках: права пользователей, лимиты подписки, протухшие сессии, память сервера и сеть до Telegram. Каждую поломку я закрыл правилом или кодом. Вот что было у меня.

| Что случилось | Что сделал |
|---|---|
| Claude Code 2.1.251 не принял модель Opus 5.5 | Обновил до 2.1.289 от root, после каждого обновления проверяю нужную модель |
| `claude update` от пользователя бота падал без прав npm | Обновляю только от root, автообновлению не доверяю |
| Лимит подписки остановил монтаж на шаге 4 из 7 | Кнопка «Продолжить» и автоожидание сброса лимита |
| Протухшая сессия ломала продолжение разговора | Бот повторяет запрос с новой сессией |
| Два Claude сразу съели бы память сервера | Очередь на одного, остальные задачи ждут |
| Пачка готовых роликов после простоя упёрлась в ограничение Telegram на частоту сообщений | Бот находит ролики без карточки и отправляет их заново |

Что я бы проверил заранее, если собираешь такого сотрудника впервые:

- **Переменная `ANTHROPIC_API_KEY`.** Её не должно быть в окружении бота, иначе подписка не работает.
- **Версия Claude Code.** Новая модель в подписке не значит, что старый Claude Code её примет.
- **Список разрешённых инструментов.** Начни с узкого и расширяй по одной задаче.
- **Состояние на диске.** Перезапуск бота не должен обрывать задачи.
- **Статус в чате.** Если агент молчит, ты должен видеть, где он встал: в очереди, на лимите или на ошибке.

Лимит подписки при таком режиме работы ты почувствуешь точно. Длинные задачи, вроде монтажа, съедают окно быстрее, чем разговор. Поэтому тяжёлое у меня идёт по расписанию и с автопродолжением, а лёгкое отвечает сразу.

## С чего начать, если хочешь такого сотрудника себе?

Начни с одной темы и одной задачи. Например, бот в личке, который по твоему сообщению правит страницу в Notion. Когда это работает неделю без сбоев, добавляй темы, файлы и навыки.

Порядок, который я бы повторил:

1. Сервер на Ubuntu, отдельный пользователь, Node.js и Python.
2. Claude Code от root, вход по подписке от пользователя бота, проверка `claude -p "привет"`.
3. Проверка окружения на `ANTHROPIC_API_KEY`.
4. Рабочая папка с `CLAUDE.md`: проект, базы, правила, запреты.
5. Бот с очередью на одного, `--resume` по темам и узким `--allowedTools`.
6. Служба systemd и состояние в файле.
7. Локальный Bot API, если нужны файлы больше 20 МБ.
