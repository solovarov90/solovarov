Управлять Claude Code с телефона можно через Telegram-бота на недорогом сервере: бот принимает твоё сообщение и передаёт его в claude -p, а Claude Code на сервере вошёл в аккаунт по обычной подписке Claude Pro. Оплаты за каждый запрос по API нет, ты платишь только подписку и сервер. Я так работаю с 30 сентября 2026 года: ставлю задачи по коду, правлю базы в Notion, запускаю монтаж роликов и пишу статьи прямо со смартфона.

Ниже разбираю, как устроен мой ИИ-штаб: какие службы стоят на сервере, как войти в Claude на машине без экрана, что я делаю из телефона каждый день и что ломалось. Всё описанное работает у меня каждый день: штаб живёт внутри медиа-конвейера ii.systema, и эту статью тоже написал он.

Зачем запускать Claude Code на сервере, а не на личном ноутбуке?

Сервер работает круглосуточно и доступен откуда угодно, ноутбук нет. Claude Code на ноутбуке живёт, пока открыта крышка и запущен терминал. На сервере он ждёт задачу всегда, а ты пишешь ему из любого места, где есть Telegram.

Что это дало мне на практике:

  • Задачи из дороги. Увидел ролик, который хочу разобрать, и кинул ссылку в тему. Вспомнил правку в сценарии и наговорил голосовое. Компьютер для этого не нужен.
  • Фоновые задачи без присмотра. Разбор референсов, переписывание сценариев, утренний отбор тем по трендам идут сами по расписанию.
  • Одно место для всего. Вместо десятка вкладок у меня одна группа в Telegram с темами. Каждая тема отвечает за свой участок работы.

Мой компьютер в этой схеме остался, но только для тяжёлого: монтаж роликов идёт на его видеокарте. Всё, что про текст, код и базы, живёт на сервере.

На то, что спрос на такое управление растёт, указывают и открытые проекты. Например, Orca обещает следить за агентами вроде Claude Code с телефона, получать уведомления и отправлять следующие задачи откуда угодно (так написано на странице проекта 19.10.2026). Я собрал свою связку раньше, чем узнал про такие инструменты, и на своём боте мне проще: он знает мои темы, мои базы и мои правила.

Как связать Telegram и Claude Code без оплаты API-токенов?

Связка делается так: на сервере стоит Claude Code, ты один раз входишь в него своим аккаунтом Claude Pro, а Telegram-бот на каждое сообщение запускает команду claude -p с текстом задачи. API-ключ при этом не нужен вовсе. API здесь это платный программный доступ к модели, где каждый запрос оплачивается по объёму текста.

claude -p это неинтерактивный режим Claude Code: задача передаётся одной строкой, Claude выполняет её и печатает результат. В документации Anthropic (проверено 19.10.2026) у него есть всё, что нужно боту:

  • --output-format json отдаёт ответ в виде, который бот легко разбирает;
  • --resume <id сессии> продолжает прошлый разговор, так Claude помнит контекст темы;
  • --allowedTools перечисляет инструменты, которыми агенту разрешено пользоваться.

Агентом я называю программу, которая сама решает, какие шаги сделать: прочитать файл, поправить код, сходить в Notion.

Главная ловушка с подпиской одна. Anthropic в справке предупреждает: если на машине задана переменная окружения ANTHROPIC_API_KEY, Claude Code возьмёт этот ключ вместо подписки, и запросы пойдут в оплату по API. На сервере, где раньше стояли другие проекты, это легко пропустить. Проверь окружение пользователя, от которого запускается бот.

Сколько стоит подписка: в моём гайде по Claude на 04.10.2026 записано, что Pro стоит $20 в месяц или $17 в месяц при оплате за год. Сервер для ботов у меня обходится от 500 ₽ в месяц, эту цифру я приводил в статье про медиа-конвейер.

Как устроен ИИ-штаб: архитектура сервисов на Ubuntu?

Штаб это три слоя: Telegram-группа с темами, бот-курьер на сервере и Claude Code в рабочей папке с правилами и навыками. Бот ничего не думает сам. Он принимает сообщение, понимает, из какой оно темы, и передаёт задачу Claude.

Мой сервер по записи от 30.09.2026: Hetzner, Ubuntu 22.04, 2 ядра, 3,7 ГБ памяти, из них свободно около 2,9 ГБ, диск занят на 25%. Наружу открыт только SSH, то есть вход для администратора по ключу.

Что на нём стоит:

  1. Служба ii-shtab. Бот @ii_systemaBot запущен как systemd-служба от отдельного пользователя iishtab. Systemd сам поднимает бота после перезагрузки и падения.
  2. Claude Code. Вошёл в аккаунт Claude Pro под тем же пользователем. Через коннекторы claude.ai ему доступен Notion: коннектор это готовый мост от Claude к внешнему сервису.
  3. Рабочая папка. В ней лежат CLAUDE.md с описанием проекта и правилами и папка навыков .claude/skills. Навык (скилл) это инструкция на конкретную задачу: разобрать ролик, написать статью по брифу.
  4. Локальный Bot API. С 01.10.2026 бот ходит в Telegram через свой сервер Bot API, поэтому принимает файлы до 2 ГБ вместо 20 МБ.
  5. Ключ к соседнему серверу. Разбор видео идёт на другом сервере. Ключ штаба к нему разрешает ровно одну команду: запустить разбор ссылки. Больше ничего с ним сделать нельзя.

Темы группы на старте 30.09.2026 были такие: «Референсы» (ссылки на ролики уходят на разбор), «Штаб» (разговор, правки Notion, голосовые), «Сценарии», «Журнал», «Система». Потом добавились «Дубли», «Монтаж», «Выкладка» и другие, но принцип не менялся: одна тема, один участок.

Внутри бота самое важное это функция запуска Claude. Она собирает команду claude -p, добавляет правила темы, список разрешённых инструментов и номер прошлой сессии. Если сессия протухла, бот начинает разговор заново. И ещё одна строка, без которой сервер с 4 ГБ памяти не выжил бы: очередь на одного. Одновременно работает только один Claude, остальные задачи ждут.

Как авторизовать Claude Pro на сервере без графического интерфейса?

Войти можно прямо в терминале по SSH: запускаешь Claude Code, он печатает ссылку, ты открываешь её в браузере на телефоне или ноутбуке, входишь в аккаунт и вставляешь полученный код обратно в терминал. Браузер на самом сервере не нужен.

Порядок, который работает у меня:

  1. Зайди на сервер по SSH и переключись на пользователя, от которого будет работать бот. Входить надо именно под ним: вход сохраняется в его домашней папке.
  2. Поставь Claude Code: npm install -g @anthropic-ai/claude-code.
  3. Запусти claude (или claude auth login). В терминале появится ссылка для входа.
  4. Открой ссылку где угодно, войди аккаунтом с подпиской Pro и скопируй код в терминал.
  5. Проверь claude -p "привет" от того же пользователя. Ответ пришёл, значит бот тоже сможет.

Здесь я споткнулся о права. Пакеты npm у меня ставятся от root, а бот работает от iishtab. Поэтому штатное claude update от пользователя падало: ему некуда писать. Обновляю я командой от root, об этом ниже в разделе про Opus 5.5.

Если у тебя в терминале вставка в ssh -t не проходит, открой SSH в отдельном окне. У меня встроенная панель терминала в приложении не передавала ввод в SSH, и код входа приходилось вставлять из обычного окна командной строки.

Какие задачи решает Telegram-штаб прямо из смартфона?

Из телефона я делаю почти всё, кроме съёмки: разбираю ролики, пишу и переписываю сценарии, правлю базы в Notion, запускаю монтаж и выкладку, готовлю статьи для блога. Каждая задача это сообщение или кнопка в своей теме.

Что идёт через штаб каждый день:

  • Разбор референсов. Кидаю ссылку на чужой ролик, сервер скачивает его, расшифровывает и кладёт разбор строкой в «Контент-план».
  • Сценарии. С 04.10.2026 хуки, текст и концовки пишет Claude Opus 5.5 по подписке. На тесте ролик REEL-19 переписан примерно за 33 секунды. Если Opus недоступен, бот берёт Gemini.
  • Правки голосом. Наговариваю голосовое в «Штаб», бот превращает его в текст и отдаёт Claude, тот правит страницу в Notion и докладывает.
  • Монтаж. С 01.10.2026 под дублем есть кнопка «Смонтировать». Бот кладёт задачу в общую папку, на компьютере её подхватывает Claude Code со скиллом монтажа, а готовый ролик возвращается в тему.
  • Статьи. С 18.10.2026 на том же сервере работает SEO-штаб. Статью пишет claude -p со скиллом блога, это занимает 10–25 минут, потом я смотрю превью и сам жму «Выложить».

Самое ценное здесь в правилах. В рабочей папке лежит CLAUDE.md с описанием проекта, и каждая новая сессия читает его первой. Поэтому сообщение «перепиши REEL-6» Claude понимает без пояснений: где лежит сценарий, по каким правилам писать, куда сохранить.

Как это выглядит со стороны всего конвейера, я показывал в кейсе ii.systema. Автоответы по кодовому слову, которые тоже управляются из этой группы, разобраны в отдельной статье.

Проверил на себе: штаб на подписке и поломка при переходе на Opus 5.5

Штаб работает у меня с 30.09.2026 на одном сервере и одной подписке Claude Pro. Первая серьёзная поломка случилась через четыре дня, когда я решил перевести сценарии на новую модель.

Как это было. 04.10.2026 я переводил написание сценариев с Gemini Flash на Claude Opus 5.5. Тексты от Gemini звучали фальшиво, и я хотел модель сильнее. Бот стал вызывать claude -p --model claude-opus-5-5, а Claude Code на сервере ответил отказом. На сервере стояла версия 2.1.251, и она такой модели не знала.

Дальше выяснилось второе. Штатная команда claude update от пользователя бота падала: npm-пакеты ставились от root, и у пользователя не было прав их менять. Автообновление молча не работало с первого дня.

Что сделал:

  1. Обновил Claude Code от root: npm install -g @anthropic-ai/claude-code@latest. Версия стала 2.1.289.
  2. Проверил вызов Opus 5.5 от пользователя бота. Сценарий REEL-19 переписался примерно за 33 секунды, текст чистый.
  3. Записал правило в журнал изменений: обновлять только так, от root, и после обновления проверять вызов нужной модели от пользователя бота.

Вывод для тебя: новая модель в подписке не значит, что старый Claude Code её примет. Если бот на сервере вдруг перестал отвечать после смены модели, первым делом посмотри версию claude --version и обнови её.

Вторая история про лимит. 01.10.2026 первый монтаж из чата упёрся в лимит подписки на шаге 4 из 7. В подписке Pro лимит считается окнами по 5 часов, так записано в моём гайде по Claude на 04.10.2026. Я добавил кнопку «Продолжить»: Claude поднимает ту же сессию и не повторяет готовые шаги. В тот же день раннер научился сам ждать сброса лимита и продолжать без меня.

Что может пойти не так: права доступа, лимиты контекста и зависшие фоновые сессии?

Ломается связка на стыках: права пользователей, лимиты подписки, протухшие сессии и память сервера. Каждую такую поломку я закрыл правилом или кодом, вот список.

Что случилось Что сделал
Claude Code 2.1.251 не принял модель Opus 5.5 Обновил до 2.1.289 от root, проверяю модель после каждого обновления
claude update от пользователя бота падал без прав npm Обновление только от root, автообновление не жду
Лимит подписки остановил монтаж на шаге 4 из 7 Кнопка «Продолжить» и автоожидание сброса лимита
Протухшая сессия ломала продолжение разговора Бот повторяет запрос с новой сессией
Два Claude сразу съели бы память сервера Очередь на одного, остальные задачи ждут

Отдельно про права. В режиме claude -p подтверждение спросить не у кого. Поэтому разрешённые инструменты прописаны заранее в --allowedTools, и всё, чего нет в списке, Claude не сделает. Опасные действия я специально не отдаю. Деплой бота и включение служб systemd делаю сам: встроенная проверка Claude Code в автоматическом режиме и так блокирует ему такие шаги, и я считаю это правильным.

Про контекст. Чем длиннее разговор в одной сессии, тем быстрее он съедает лимит. Я держу отдельную сессию на каждую тему и не тащу всю историю в каждый запрос: правила проекта лежат в CLAUDE.md, а не в переписке.

Про зависания. У каждого запуска Claude в боте есть таймаут. Не уложился, и бот убивает процесс и пишет в тему, что случилось. Без этого одна зависшая задача держала бы очередь, и все остальные ждали бы вечно.

С чего начать сборку собственного автономного штаба?

Начни с одной темы и одной задачи, которую делаешь каждый день. Штаб из двадцати функций не собирается за вечер, а бот, который выполняет одну твою рутину, собирается.

Порядок, который я бы повторил:

  1. Возьми сервер с 2 ядрами и 4 ГБ памяти. Ставь Ubuntu, открой наружу только SSH.
  2. Заведи отдельного пользователя для бота и войди в Claude Code под ним по подписке. Проверь, что ANTHROPIC_API_KEY в окружении нет.
  3. Напиши CLAUDE.md на одну страницу: что за проект, где что лежит, какие правила. Это память агента между сессиями.
  4. Собери бота-курьера на одну тему: сообщение уходит в claude -p, ответ возвращается в тему. Добавь очередь на одного и таймаут.
  5. Ограничь инструменты через --allowedTools. Начни с чтения и правки файлов, остальное добавляй, когда понадобится.
  6. Подними его службой systemd, чтобы бот переживал перезагрузку.
  7. Добавляй темы по одной, когда первая заработает без тебя неделю. И веди журнал изменений: через месяц он скажет, что и когда сломалось.

Если собирать это самому некогда или не хочется разбираться с правами и лимитами, напиши слово «система» в личные сообщения t.me/solovarov. За 30 минут разберём твою инфраструктуру и решим, каких ИИ-агентов перенести на сервер под твои задачи.

Частые вопросы

Законно ли запускать Claude Code под подпиской Claude Pro на удалённом сервере?

Anthropic прямо пишет в справке, что подписка Pro или Max покрывает Claude Code в терминале: входишь тем же аккаунтом, что и в чат. Сервер в моём случае это тот же терминал, только в облаке, и работает в нём один человек, я. Условия использования меняются, поэтому перед запуском перечитай их на сайте Anthropic сам.

Сколько ресурсов сервера требует работа связки бота и Claude Code?

У меня штаб живёт на сервере Hetzner с 2 ядрами и 3,7 ГБ памяти, по данным на 30.09.2026 из них свободно около 2,9 ГБ. Чтобы память не кончилась, бот пускает только одну сессию Claude за раз, остальные задачи ждут очереди. Диск занят на 25%, свободно около 27 ГБ.

Нужно ли держать домашний компьютер включенным для управления с телефона?

Для разговора, правок в Notion, сценариев и статей нет: всё это делает сервер. Компьютер нужен только для тяжёлого, у меня это монтаж роликов на видеокарте. Туда бот отправляет задачу через синхронизацию папок, и если компьютер выключен, задача ждёт, пока он включится.

Что делать, если Claude Code запрашивает подтверждение на выполнение консольной команды?

В режиме claude -p спросить некого, поэтому разрешения задаются заранее флагом --allowedTools: какие инструменты агенту можно, какие нельзя. Если инструмента нет в списке, Claude его не вызовет и скажет об этом в ответе. Опасные вещи вроде деплоя и включения служб я оставляю себе руками.

Как пересылать файлы и код из Telegram в проект на сервере?

Бот скачивает файл и кладёт его в рабочую папку, а Claude дальше работает с ним как с обычным файлом. Обычный облачный Bot API отдаёт ботам файлы до 20 МБ, поэтому с 01.10.2026 у меня на сервере свой локальный Bot API, он принимает файлы до 2 ГБ. Так в штаб приезжают даже сырые видеодубли.

Можно ли использовать этот способ без платной подписки Claude Pro?

Нет. Для запросов в Claude Code нужна платная подписка Claude (Pro, Team или Enterprise) либо аккаунт console.anthropic.com с балансом API. Второй путь работает, но тогда каждый запрос оплачивается по токенам, а вся идея штаба как раз в фиксированной цене подписки.
